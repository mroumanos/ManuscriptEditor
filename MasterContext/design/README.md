# Design Context — Manuscript Editor

Deep UI/UX design guidance for the Manuscript Editor app: the ranked principles,
per-surface design rules, visual tokens, and interaction patterns that make the
product bar ("professional, modern, trustworthy") concrete and testable. Load this
folder as standing context for any design or UI implementation work.

> **Provenance & precedence.** This folder began as autogenerated generic
> manuscript-editor design docs and has been revised to fit *this* product. The
> numbered Master Context docs own **requirements and domain**:
> [`02-domain-model.md`](../02-domain-model.md),
> [`04-information-architecture.md`](../04-information-architecture.md),
> [`05-features.md`](../05-features.md), and [`glossary.md`](../glossary.md) win
> any conflict with this folder. This folder owns **design depth** — the *how it
> should feel and why* — and extends [`06-design-system.md`](../06-design-system.md)
> (quick visual reference) and [`07-wireframes.md`](../07-wireframes.md) (layouts).

## How to use these docs

- **Read order for a first pass:** 00 → 01 → 02, then whichever doc the current
  work touches, then [`../06-design-system.md`](../06-design-system.md) (the
  canonical visual language — color, type, spacing, components) and 07 before
  building any UI.
- **Terminology is binding and lives in [`glossary.md`](../glossary.md)** —
  journal, cut, version, lineage, sync, rollback, view, requirements, checks,
  notes. Do not reintroduce generic-editor vocabulary (see 00 §4 for the
  forbidden-terms table).
- **Amending:** change the source doc, don't fork guidance into new files. If a
  requirement changes, update the numbered Master Context doc *and* the affected
  doc here in the same change.

## The model in one sentence

> The user writes the **Source** journal, cuts per-journal copies that each meet a
> target's **requirements**, saves **versions** within each journal, keeps
> derivations honest via **lineage** (sync/rollback), watches **Checks** go green,
> and ships a self-contained submission **package** via the journal's **export
> outline**.

Every screen should be explainable as a view onto this model.

## What is deliberately NOT decided here

Domain schema, feature acceptance criteria, architecture, and phasing — those live
in the numbered Master Context docs. This folder constrains *look, feel, and
interaction behavior*; any implementation that satisfies the budgets in 00 §3.6
and [`10-performance-plan.md`](../10-performance-plan.md) is acceptable.
